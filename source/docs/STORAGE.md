# Spark storage and phone offloading

Proof Bank: 12 screenshot and 24 text slots per player; 400 total bank items across all players. The global cap reserves roughly 100 MiB by budgeting 256 KiB per item. Screenshots have a 180,000-byte cap; text has a 12,000-character cap. Large fields are excluded from indexing by firestore.indexes.json. This provides substantial bank headroom below the 1 GiB project allowance; it does not bound unrelated records or monitor actual project storage.

Save and delete transactions change sparkBankCapacity/global with the item. Rules reject standalone counter resets, missing increments, out-of-range IDs, oversized bytes and cross-account reads. No counter reset is included in the UI. Deleting a player account through the Firebase Console does not automatically delete Firestore subcollections; any administrative cleanup must keep the counter consistent.

Full user slots or global cap: reject save and show the phone/device alternative. Firebase resource-exhausted errors: state that storage or daily usage is full and the save failed. Data stays in the form so the original screenshot or note can be downloaded. The player can also export the existing bank as a standard ZIP. After checking the downloaded ZIP, they confirm offload; deletion is conditional on each item's saved timestamp and does not change missions, evidence submissions, XP or paid access. If cleanup partly fails, remaining items stay and the player gets a partial-progress message.

On iPhone/Android, the browser controls where downloads are saved and may require opening Files/Downloads or choosing Save to Files. The app cannot prove that a download completed, so it never clears on the download click. This flow still needs real-device acceptance testing.

Firestore free quotas documented at https://firebase.google.com/docs/firestore/quotas include 1 GiB storage, 50,000 reads/day, 20,000 writes/day and 20,000 deletes/day. Other limits and network usage apply. Screenshots are stored as small private Firestore byte fields, not Firebase Storage. At account-wide quota exhaustion reads or deletes may fail as well. Spark is not upgraded by this game. Review the Firebase Usage dashboard and service notices; the bank counter is not a replacement for project-wide monitoring.

Community, proofs, guide memories, billing audit records and player accounts also consume storage. This package cannot guarantee unlimited players remain inside free quotas, and no such claim should be used in launch copy. The shared bank cap intentionally stops well before the overall allowance. Reduce it before launch if the existing project already has little free capacity; change both client and rules together and do not lower it below existing item count without a planned cleanup.
